# Hotfix: Multi-city теперь делает unordered route optimization

Пользовательская ценность репозитория сохранена и вынесена в главный сценарий:

> Пользователь указывает список городов, которые хочет посетить, **без порядка**, а бот перебирает порядок посещения и выбирает самый дешёвый выполнимый маршрут.

## Новый UX

Главная кнопка теперь:

```text
🧭 Multi-city: найди порядок городов
```

Примеры:

```text
из СПб посетить Стамбул, Шанхай, Бангкок 06.07-25.07 по 2-4 дня до 120000
СПб: Стамбул, Шанхай, Бангкок 06.07-25.07 до 1 пересадки
из LED через IST, SHA, BKK 06.07-25.07 без возврата
```

## Как работает алгоритм

1. Парсер извлекает:
   - стартовый город;
   - unordered список городов для посещения;
   - общее окно дат;
   - min/max дней в каждом городе;
   - общий бюджет;
   - max пересадок и max длительность на одно плечо;
   - нужен ли возврат в стартовый город.
2. Клиент запрашивает дешёвые офферы для всех направленных пар городов.
3. Для каждого возможного порядка посещения строится последовательность плеч.
4. Beam search выбирает конкретные перелёты так, чтобы:
   - даты шли по порядку;
   - после прилёта в город выдерживалась остановка `min_stay_days..max_stay_days`;
   - общий маршрут укладывался в окно дат;
   - общий бюджет не превышался.
5. Бот показывает top маршрутов с total price и кнопками на каждое плечо.

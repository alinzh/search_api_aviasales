# Round-trip UX hotfix

Добавлена обработка пользовательского формата:

```text
из СПб в Китай и обратно 06.07-14.07 до 90000
```

Теперь `и обратно` не попадает в название направления. Парсер трактует этот запрос как:

- направление: `Китай`;
- туда: `06.07.2026`;
- обратно: `14.07.2026`;
- бюджет: общий бюджет за пару туда+обратно.

Также поддерживается гибкий формат с двумя окнами дат:

```text
из СПб в Китай туда 06.07-08.07 обратно 14.07-16.07 до 90000
```

В этом случае бот ищет дешевое плечо туда внутри первого окна и обратное плечо внутри второго окна.

## Что изменилось

- `SearchQuery` получил поля `return_to_origin`, `return_date_from`, `return_date_to` и `is_round_trip`.
- `quick_parser.py` распознает `и обратно`, `туда-обратно`, `обратно`, `назад`, `return`, `round trip`.
- `TravelpayoutsClient.search_round_trip()` собирает пару `origin → destination` + `destination → origin`.
- Для стран/регионов round-trip работает как discovery: перебираются города страны, затем выбирается лучшая пара туда+обратно.
- В Telegram добавлены карточки туда-обратно с двумя кнопками: открыть билет туда и открыть обратный билет.
